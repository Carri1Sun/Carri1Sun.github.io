## Plan 如何打动用户

### 用户什么时候需要 Plan
其实可以从人跟人交互的角度去思考这个问题
比如上司和下属相处，下属向上司请示问题的时候，或者上司向下属布置任务的时候，被请示的一方都会分析发号施令者是否有未说出的情况，进行几次反问或者直接给出一个他自己的分析看对方是否要改动。
所以 Plan 是一种在人类组织里早就存在的协作机制：当一个人把任务交给另一个人时，接收任务的人不会机械地只按照字面意思行动，而是会判断对方真正想解决什么问题、有哪些没有说出口的条件、哪些事情自己可以做主、哪些事情一旦理解错就应该提前确认。

## Plan 如何 Prompting（怎么样让模型输出好的 Plan）
Plan 这个东西是由模型输出的，一定要做效果评测的
这个东西做评测工作，一般会面临工程 hacking 的问题，就是如果在 prompt 里面写完备评测题目，那评测题目肯定就一定能过。
我一般做这样的标准效果评测流程：
我会根据自己的想法，写好 prompt
我确定几个题目，几个场景，测试好这份 prompt 在这几个场景下的效果
如果效果好，就认为可以，如果效果还有欠缺觉得可以更好，思考如何更好的 prompt
我认为不能以先确定题目，后工程的方式去开展评测-工程这种开发流程
